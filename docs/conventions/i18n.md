# 多语言（i18n）

App 内运行时切换 **简体中文 / English**，覆盖界面文案与通知栏文案。

## 结构

```
src/i18n/
  provider.tsx        I18nProvider + useTranslation / useI18n / getTranslator
  languages.ts        Language 类型、语言归一、字典取值 lookup
  index.ts            对外出口
  dictionaries/
    zh.ts             基准语言，键必须齐全
    en.ts             英文翻译，键与 zh 严格一致
```

语言偏好存在 AsyncStorage 的 `rememberyao-lang`（**不进 SQLite**）：它是设备级偏好，和业务数据迁移无关，混在一起会让首次迁移变复杂。

## 用法

```tsx
import { useTranslation } from "@/i18n";

function Screen() {
  const t = useTranslation();
  return <Text>{t("medication.detail")}</Text>;
}
```

带插值：

```tsx
t("medication.filterAll", { count: medications.length })
// zh: "全部 {count}"   en: "All {count}"
```

**`t` 的路径是类型安全的**：只接受 `zh.ts` 里存在的键，拼错或漏翻在 `tsc` 就报错，不会静默显示 key。

### React 之外用翻译

通知调度、数据层拼快照文案这些地方拿不到 hook，用 `getTranslator()`：

```ts
import { getTranslator } from "@/i18n";
const t = getTranslator();
const body = t("notification.body", { person, medication, amount });
```

`getTranslator()` 返回的是**当前**语言，`I18nProvider` 每次渲染会更新它。

## 硬规则

1. **禁止在屏幕/组件里写死中文或英文 UI 文案**，一律走 `t()`。注释里的中文不算。
2. **禁止直接 import 词典文件**（`@/i18n/dictionaries/zh`），只用 `useTranslation` / `getTranslator`。
3. **加词条必须 zh + en 同时加**，键路径完全一致。zh 是基准语言，`Path` 类型由它推导；en 可以用 `satisfies` 反向校验，但**不能给 zh 加 `: TranslationTree` 注解** —— 那会把字面量类型拓宽成索引签名，`Path` 直接退化成 `never`，全仓库的 `t()` 调用一起报错。
4. **枚举值 → 展示文案走映射表**，不要拼路径字符串：

   ```ts
   // src/lib/store.ts
   const TYPE_LABEL_PATH: Record<MedicationType, Path> = {
     blister: "medication.typeBlister",
     // ...
   };
   export function medicationTypeLabel(type: MedicationType, t: Translate): string {
     return t(TYPE_LABEL_PATH[type]);
   }
   ```

   标签函数需要 `t` 参数，由调用方（组件）传入。

5. **日期/星期走 `Intl`，不要硬编码**。中文「9月5日」和英文「Sep 5」语序不同，用两个独立词条或 `Intl.DateTimeFormat`：

   ```ts
   new Intl.DateTimeFormat("en-US", { month: "short", day: "numeric" }).format(date);
   ```

6. **通知栏文案要在语言切换后重注册**。渠道名和「已服用 / 跳过」按钮标题在 `setNotificationCategoryAsync` 时就固化了，换语言不重注册会继续显示旧语言。`src/app/_layout.tsx` 监听 `language` 变化调 `registerLocalizedNotificationTexts()`。

## 添加新词条的步骤

1. 在 `zh.ts` 对应分组加键（值写中文）。
2. 在 `en.ts` 同一分组加同名键（值写英文）。
3. 组件里 `t("分组.键")`。
4. `bun run check` —— 漏翻/拼错在这一步就会报出来。

## 为什么不用 i18next / lingui

字典不到 250 个键、只有两种语言，运行时切语言是硬需求（用户不跟系统语言走）。自建一个 `t()` 换来的是：零额外依赖、路径类型安全、`getTranslator()` 能在通知层复用。等语言数超过 5 种或需要复数/性别变化规则时再评估 `i18next`。
